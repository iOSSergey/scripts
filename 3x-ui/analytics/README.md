# Xray access live

`xray-access-live.py` — цветной просмотр подключений из Xray / 3x-ui access.log.
Нужны Python 3.8+ и системная команда `tail`, установка пакетов через pip не нужна.

```bash
# Последние 10 строк /usr/local/x-ui/access.log, затем новые записи
sudo ./xray-access-live.py

# Только новые записи из указанного файла; продолжает чтение после ротации
./xray-access-live.py /path/to/access.log -n 0

# Использование в pipeline (минус означает чтение stdin)
tail -F /usr/local/x-ui/access.log | ./xray-access-live.py -

# Фильтры можно комбинировать
./xray-access-live.py --user 'Ishina' --route lobasto-v6
./xray-access-live.py --route direct

# Пустая строка между блоками по 5 подключений
./xray-access-live.py --group-size 5

# Промежуток между каждой записью / сплошной вывод
./xray-access-live.py --group-size 1
./xray-access-live.py --group-size 0

# Последние 50 строк без дальнейшего наблюдения
./xray-access-live.py -n 50 --once
```

Пример вывода без ANSI-цветов:

```text
DATE / TIME                 USER                              ROUTE               SOURCE                      DESTINATION
2026/09/25 09:51:03.314954  Natalie Android                   [lobasto-v6]        95.24.156.231:21006       → i.instagram.com:443
2026/09/25 09:51:03.476708  Ishina iPhone Pro 5               [lobasto-v6]        46.138.25.182:3839        → [2001:67c:4e8:f004::b]:443
2026/09/25 09:51:03.632832  Yaroslav Tarasov - Gleb Android   [direct]            91.79.36.14:27723         → 8.8.8.8:53
```

Колонки: дата и время, имя пользователя, исходящий маршрут, адрес клиента (`SOURCE`)
и `→` адрес назначения. В `SOURCE` выводятся IP и порт клиента из поля `from`;
служебный префикс `tcp:` / `udp:` убирается. Поддерживаются IPv4 и IPv6.
Дата и время сохраняются как в логе, включая доли секунды и исходный часовой пояс.
После стрелки показывается домен или IP с портом из лога; если записан только IP,
домен по нему не определяется.
Имя берётся целиком из `email`, включая пробелы. Ширина колонок даты, имени,
маршрута и источника — 26, 32, 18 и 24 позиции. Длинные значения переносятся на продолжение
строки в той же колонке без обрезки; адрес назначения выводится целиком.
Если имя отсутствует, выводится `—`.
Цвет пользователя постоянный; `direct` зелёный, остальные маршруты пурпурные,
`block` / `blocked` / `blackhole` красные.
Это поток событий, а не список активных сессий; повторные события сохраняются.

По умолчанию цвета включены только в терминале. `--color always` принудительно
включает цвета, `--color never` или `NO_COLOR=1` отключает автоматические цвета.
Заголовки колонок появляются только в терминале; `--no-header` отключает их.
Старый флаг `--one-line` принимается для совместимости и ничего не меняет.
В интерактивном терминале пробел переключает паузу без нажатия Enter.
Во время паузы скрипт продолжает читать лог и пропускает события;
очередь записей в памяти не накапливается. `Ctrl+C` завершает просмотр и
восстанавливает настройки терминала. Клавиши работают и при чтении через pipe:
они считываются отдельно из `/dev/tty`. Если терминала нет или его режим нельзя
изменить, просмотр идёт как прежде.
Вывод не буферизуется.
По умолчанию пустая строка разделяет блоки по 10 отображённых подключений.
`--group-size N` меняет размер блока; `1` разделяет каждую запись, `0` убирает
промежутки. Записи появляются сразу, без ожидания заполнения блока.
Переносы длинных полей не считаются отдельными подключениями.

`--user` ищет подстроку без учёта регистра, `--route` требует точного совпадения.
Служебные записи с исходящим маршрутом `api` всегда скрыты (без учёта регистра),
в том числе при `--route api`. Обращения пользователей к доменам вида `api.example.com`
через обычные маршруты остаются видимыми. Скрытые записи не учитываются в размере блока.
Нераспознанные строки пропускаются.
Для stdin параметры `-n` и `--once` не применяются: поток читается до EOF.
При запуске с файлом `-n` применяется до фильтров. Для ротации используется
`tail -F`; его диагностические сообщения остаются в stderr.
